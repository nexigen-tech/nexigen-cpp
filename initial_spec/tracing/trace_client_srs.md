# Спецификация требований к клиентской библиотеке трассировки (nexigen::trace SDK)

## 1. Введение и область применения
Настоящий документ определяет требования к функциональности, модели памяти и программному интерфейсу (API) встраиваемой клиентской библиотеки **`nexigen::trace`**. Библиотека обеспечивает профилирование времени выполнения участков кода (Timeline Spans) и сквозное отслеживание цепочек обработки данных между независимыми процессами (Distributed Pipeline Tracing) с использованием скрытых заголовков **Eclipse iceoryx2**. Архитектура гарантирует наносекундные накладные расходы, отсутствие динамических аллокаций и полную совместимость с потоками жесткого реального времени.

## 2. Инструментация кода и профилирование (RAII Spans & Instant Events)

*   **REQ_TRCC_001: Автоматический замер длительности областей видимости (RAII Scoped Spans)**
    *   **Описание:** Библиотека должна предоставлять макросы и классы на базе идиомы RAII для автоматической фиксации времени начала и окончания выполнения функции или блока кода.
    *   **Критерий приемки:** 
        1. Вызов макроса `nexigen_TRACE_SCOPE("SpanName")` создает легкий объект на стеке потока.
        2. В конструкторе считывается текущая метка монотонного времени (`start_timestamp_ns`) и сохраняется идентификатор родительского спана.
        3. В деструкторе (при выходе из функции/блока) вычисляется длительность (`duration_ns = end_ns - start_ns`) и формируется бинарная запись в разделяемой памяти.

*   **REQ_TRCC_002: Мгновенные события и счетчики на таймлайне (Instant Events & Track Counters)**
    *   **Описание:** Помимо протяженных во времени интервалов, библиотека должна поддерживать фиксацию точечных событий во времени и изменение числовых параметров для отображения на единой оси времени.
    *   **Критерий приемки:** 
        1. Макрос `nexigen_TRACE_EVENT("FrameDropped")` фиксирует одиночную временную отметку на таймлайне потока.
        2. Макрос `nexigen_TRACE_COUNTER("GPU_Queue_Depth", value)` записывает точку изменения значения для построения синхронного графика в Perfetto UI прямо под диаграммой Ганта потоков.

*   **REQ_TRCC_003: Мгновенное отсечение при выключенной трассировке (Zero-Cost Disabled State)**
    *   **Описание:** В штатном боевом режиме, когда запись детальной трассировки не активна, инструментация в коде не должна создавать измеримой нагрузки на процессор.
    *   **Критерий приемки:** 
        1. Первой инструкцией макроса выполняется атомарное чтение глобального флага активности категории трассировки из разделяемой памяти (`std::memory_order_relaxed`).
        2. При выключенной трассировке вызов сводится к одной процессорной инструкции сравнения и перехода (`<= 1 нс`), без чтения аппаратных таймеров и без обращения к `iceoryx2`.

## 3. Сквозная трассировка конвейеров данных через iceoryx2 (End-to-End Causality)

*   **REQ_TRCC_004: Скрытый заголовок трассировки в пакетах связи (iceoryx2 Custom Header)**
    *   **Описание:** Каждый сэмпл данных, передаваемый через модуль `nexigen::com` (`iceoryx2`), должен сопровождаться системным мета-заголовком трассировки, невидимым для прикладной структуры данных разработчика.
    *   **Критерий приемки:** 
        1. При конфигурировании сервиса `iceoryx2::service::Builder::publish_subscribe` используется механизм пользовательских заголовков (`with_custom_header::<TraceHeader>()`).
        2. Структура `TraceHeader` (32 байта, `TriviallyCopyable`) содержит:
            *   `trace_id` (`uint64_t`): Уникальный сквозной идентификатор цепочки событий (рождается на источнике, например, при чтении кадра с камеры или лидара).
            *   `source_span_id` (`uint64_t`): Идентификатор спана процесса-отправителя, породившего пакет.
            *   `publish_timestamp_ns` (`uint64_t`): Точное время публикации сэмпла.
            *   `sequence_number` (`uint32_t`): Порядковый номер пакета в канале.

*   **REQ_TRCC_005: Автоматическое наследование контекста в потоке (Thread-Local Context Propagation)**
    *   **Описание:** Проброс `trace_id` от входного сообщения к выходному внутри процесса должен происходить автоматически без необходимости передавать `trace_id` через аргументы пользовательских функций.
    *   **Критерий приемки:** 
        1. Когда подписчик вызывает `subscriber.receive()` в `nexigen::com`, библиотека автоматически извлекает `TraceHeader` из полученного сэмпла и записывает `trace_id` и `source_span_id` в локальное хранилище текущего потока (`thread_local TraceContext current_ctx`).
        2. Все спаны (`nexigen_TRACE_SCOPE`), открываемые в этом потоке во время обработки сэмпла, автоматически помечаются этим `trace_id`.
        3. Когда этот же поток публикует результат своей работы в следующий канал `nexigen::com` (`publisher.send()`), библиотека автоматически берет текущий `trace_id` из `thread_local` и вписывает его в `TraceHeader` уходящего пакета.
        4. При старте новой цепочки на источнике данных (драйвере сенсора) вызов `nexigen_TRACE_NEW_ROOT("LidarScan")` генерирует новый уникальный `trace_id`.

*   **REQ_TRCC_006: Замер времени ожидания в очереди IPC (IPC Queue Latency Tracking)**
    *   **Описание:** На основе метки `publish_timestamp_ns` в заголовке `TraceHeader` библиотека на стороне подписчика должна автоматически фиксировать время, которое пакет провел в разделяемой памяти до начала его чтения.
    *   **Критерий приемки:** В момент вызова `receive()` автоматически генерируется связующее событие (Flow Event), позволяющее в Perfetto UI увидеть стрелку связи от спана издателя к спану подписчика и точную задержку доставки в микросекундах.

## 4. Модель памяти и гарантии реального времени (Zero-Copy & RT Guarantees)

*   **REQ_TRCC_007: Компактная бинарная структура спана (64-byte Cache-Aligned TraceEvent)**
    *   **Описание:** Записи трассировки в разделяемой памяти должны иметь строго фиксированный размер, кратный размеру кэш-линии процессора, и не содержать динамических строк.
    *   **Критерий приемки:** 
        1. Структура `RawTraceEvent` имеет размер ровно **64 байта** (`alignas(64)`) и удовлетворяет `std::is_trivially_copyable`.
        2. Имена спанов и категорий не копируются посимвольно при каждом вызове: поскольку они являются строковыми литералами времени компиляции (`const char*`), в структуру записывается 64-битный `constexpr` хэш строки (FNV-1a), а таблица соответствия «хэш -> строка» регистрируется в сегменте памяти один раз при старте процесса.
        3. Поля `RawTraceEvent`: `trace_id` (8Б), `span_id` (8Б), `parent_span_id` (8Б), `name_hash` (8Б), `start_ts_ns` (8Б), `duration_ns` (8Б), `pid` (4Б), `tid` (4Б), `cpu_core_id` (2Б, через `sched_getcpu()`), `event_type` (1Б), `flags` (1Б), `custom_arg` (4Б).

*   **REQ_TRCC_008: Неблокирующая запись и бюджет времени (Wait-Free Ring Buffer & WCET)**
    *   **Описание:** Запись спана не должна использовать системные вызовы, мьютексы или блокировать поток при переполнении буфера.
    *   **Критерий приемки:** 
        1. Используется чтение аппаратного счетчика времени через `clock_gettime(CLOCK_MONOTONIC, ...)` через механизм `vDSO` (в пространстве пользователя без переключения в ядро ОС) либо чтение регистра `CNTVCT_EL0` (ARM) / `RDTSC` (x86).
        2. Запись в кольцевой буфер разделяемой памяти `iceoryx2` выполняется в режиме `UnableToDeliverStrategy::DiscardSample` (перезапись самых старых записей при переполнении).
        3. Полное время выполнения (WCET) записи спана в активном режиме не превышает **30–50 наносекунд**.
