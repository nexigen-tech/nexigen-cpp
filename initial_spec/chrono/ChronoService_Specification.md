# Спецификация подсистемы единого времени (ChronoService)

## 1. Назначение и цели
**ChronoService** предназначен для формирования единого временного пространства аппаратно-программного комплекса (АПК), взаимного пересчета аппаратных и программных шкал времени, синхронизации периодических процессов между узлами по **IEEE 1588 (PTP)** и записи опорных снимков времени для ретроспективного анализа («разбора полетов»).

### Ключевые архитектурные принципы
* **Единый опорный хаб (`CLOCK_MONOTONIC_RAW` / CPU TSC):** Все внутренние события, пакеты данных, трейсы, метрики и логи маркируются в монотонной шкале `CLOCK_MONOTONIC_RAW`. Данная шкала не подвергается подстройке и гарантирует строгую причинно-следственную связь.
* **Аппаратная привязка FPGA по PCIe PTM:** Таймеры модулей FPGA (`FPGA_CLOCK[0..N]`) работают свободно и привязываются к `CLOCK_MONOTONIC_RAW` на физическом уровне шины PCIe через протокол **PTM (Precision Time Measurement)** с точностью `< 15–30 нс`.
* **Межмашинная синхронизация по `CLOCK_TAI` без скачков:** Периодические процессы, требующие синфазной работы с другими машинами в сети (IEEE 1588), привязываются к шкале `CLOCK_TAI` (отсутствуют високосные секунды). После первичной привязки при старте системы скачки (`step`) системных часов запрещаются — используется только плавная подстройка частоты (`slew`).
* **Двусторонние таблицы пересчета (Forward & Reverse Models):** Для каждой пары шкал поддерживаются прямые и обратные коэффициенты преобразования в целочисленной арифметике с фиксированной точкой (`mult`, `shift`).
* **Опорные снимки времени (1 Гц):** Каждую секунду сервис фиксирует и сохраняет в журнал/поток полный атомарный срез всех шкал комплекса для точного ретроспективного восстановления хронологии событий при постобработке.

## 2. Домены времени и их назначение

| Домен / Шкала времени | Источник тактирования | Назначение в комплексе |
| :--- | :--- | :--- |
| **`FPGA_CLOCK[0..N]`** | Локальные кварцы модулей FPGA (UltraScale+ / Versal) | Аппаратные метки приема/передачи данных и событий на шинах модулей. |
| **`CLOCK_MONOTONIC_RAW`** | Аппаратный счетчик CPU TSC (не подводится) | Единый внутренний метроном. Штамповка логов, метрик, трейсов и связующий хаб для всех пересчетов. |
| **`CLOCK_MONOTONIC`** | CPU TSC + плавная коррекция ядра (не прыгает) | Внутренние таймауты ОС и интервальные задачи реального времени. |
| **`CLOCK_TAI`** | Сетевой Grandmaster IEEE 1588 (без високосных секунд) | Синхронизация периодических процессов и фазы между разными машинами комплекса (`timerfd` / `clock_nanosleep`). |
| **`CLOCK_REALTIME`** | Календарное время UTC (`TAI - tai_offset`) | Отображение времени оператору и интеграция с внешними информационными системами. |

## 3. Архитектура и потоки данных

```text
[IEEE 1588 Grandmaster] ──(Ethernet PTP)──► [NIC PHC (/dev/ptp0)]
        (опционально)                               │
                                   (PCIe PTM + phc2sys: step once, then slew)
                                                    ▼
                               [CLOCK_TAI / CLOCK_REALTIME / CLOCK_MONOTONIC]
                                                    ▲
                                    (Калибровка 10 Гц: vDSO + adjtimex)
                                                    │
[FPGA 0..N (UltraScale+)] ◄──(PCIe PTM)──► [CPU PTM Root / MONOTONIC_RAW]
        (опционально)                               │
 (ioctl: PTP_SYS_OFFSET_PRECISE)           (rdtscp / vDSO)
          ▼                                         │
  [ChronoService Daemon] ───(SeqLock)───► [/dev/shm/chrono_map]
          │                                         │
          ▼ (Снимок 1 Гц)                   (Zero-copy mmap)
  [Архив снимков времени]                  [libchrono (Прикладное ПО)]
```

## 4. Режимы работы

### 4.1. Режимы аппаратной топологии
* **`HARDWARE_FULL` (с модулями FPGA):** Обнаружены `1..N` модулей FPGA (`/dev/ptp1..N`). Активны контуры `FPGA_CLOCK[i] <-> CLOCK_MONOTONIC_RAW` по PCIe PTM и все системные контуры.
* **`HOST_ONLY` (без модулей FPGA):** Модули FPGA отсутствуют (`fpga_count = 0`). Активны системные контуры (`MONOTONIC_RAW <-> MONOTONIC <-> TAI <-> REALTIME`). Прикладное ПО использует единый API без изменения кода.

### 4.2. Режимы синхронизации (State Machine)

| Режим | Источник истины | Поведение системы | Точность |
| :--- | :--- | :--- | :--- |
| **`PTP_SYNCED`** | Внешний Grandmaster (через `/dev/ptp0`, `ptp4l` и `phc2sys`) | При старте выполняется однократная установка фазы (`step`), далее — только плавная подстройка частоты (`slew`). Все периодические задачи по `CLOCK_TAI` идут синфазно с сетью. | `< 15–30 нс` (взаимная и межмашинная) |
| **`STANDALONE`** | Локальный кварц CPU + RTC материнской платы | Внешний IEEE 1588 отсутствует. Внутренние события и FPGA сведены по `MONOTONIC_RAW`, `CLOCK_TAI` и `CLOCK_REALTIME` идут от локального кварца. | `< 15 нс` (взаимная внутри машины) |
| **`HOLDOVER`** | Последние калиброванные параметры дрейфа CPU | При потере связи с Grandmaster подстройка частоты останавливается без скачков времени; `ChronoService` продолжает экстраполяцию по последнему коэффициенту дрейфа. | `< 50–100 нс` (на интервале нескольких минут) |

## 5. Компоненты подсистемы

### 5.1. Уровень ядра (Драйверы PCIe)
* Драйверы FPGA регистрируют таймеры в Linux PHC (`/dev/ptp1..N`), активируют PCIe PTM (`pci_enable_ptm()`) и реализуют `.getcrosststamp`, возвращая атомарную пару `(FPGA_Ticks, MONOTONIC_RAW)`.
* Сетевая карта (Intel I225/I226 или NVIDIA ConnectX-7) работает через штатные драйверы (`igc` / `mlx5_core`), предоставляя `/dev/ptp0` с поддержкой PTM.

### 5.2. Фоновый демон `chronod` (`ChronoService`)
* **Исполнение:** Изолированное ядро CPU (`isolcpus`), планировщик реального времени `SCHED_FIFO`, блокировка страниц памяти `mlockall`.
* **Контур калибровки (10 Гц / каждые 100 мс):**
  1. При `fpga_count > 0` опрашивает `/dev/ptp1..N` через `ioctl(PTP_SYS_OFFSET_PRECISE)`.
  2. Считывает системные шкалы (`MONOTONIC_RAW`, `MONOTONIC`, `TAI`, `REALTIME`) через vDSO и параметры коррекции ядра через `adjtimex()`.
  3. Пропускает замеры через **2-мерный фильтр Калмана** (`offset` + `drift`) для подавления шума квантования.
  4. Вычисляет прямые (`fwd_mult`, `shift`) и обратные (`rev_mult`, `shift`) коэффициенты для перевода шкал друг в друга и публикует их в Shared Memory под защитой **SeqLock**.
* **Контур архивации снимков (1 Гц / каждую секунду):**
  * Формирует и записывает в журнал/кольцевой буфер атомарную структуру **Time Snapshot**, содержащую согласованные значения всех шкал на один физический момент времени:
    `{ FPGA_CLOCK[0..N], CLOCK_MONOTONIC_RAW, CLOCK_MONOTONIC, CLOCK_TAI, CLOCK_REALTIME, SystemTimeMode, tai_offset }`.

### 5.3. Клиентская библиотека `libchrono`
* Header-only / статическая C++ библиотека. Отображает `/dev/shm/chrono_map` через `mmap` (`PROT_READ`).
* **Вычисления:** 128-битная целочисленная арифметика (`__int128`), zero-syscall, lock-free (`< 15 нс` на вызов).
* **Основные группы функций:**
  * *Штамповка событий:* `chrono_now_mono_raw()` (через `rdtscp`).
  * *Прямой и обратный пересчет FPGA:* `chrono_fpga_to_mono_raw(id, ticks)`, `chrono_mono_raw_to_fpga(id, mono_ns)`.
  * *Взаимный пересчет системных шкал:* функции конвертации между `MONOTONIC_RAW`, `MONOTONIC`, `TAI` и `REALTIME` (включая расчет целевых меток пробуждения для `clock_nanosleep(CLOCK_TAI, TIMER_ABSTIME, ...)`).
  * *Телеметрия:* `chrono_get_last_snapshot()` (получение последнего 1-секундного среза всех шкал для встраивания в заголовки файлов данных).

## 6. Требования к настройке Linux PREEMPT_RT и служб PTP

1. **Настройка `ptp4l` и `phc2sys`:**
   * `ptp4l` синхронизирует `/dev/ptp0` с Grandmaster и передает актуальное смещение `UTC-TAI` в ядро.
   * `phc2sys` запускается с параметром запрета скачков после инициализации (`-S 0.0` при установленном первом шаге), обеспечивая плавное ведение `CLOCK_TAI`, `CLOCK_REALTIME` и `CLOCK_MONOTONIC` без разрывов.
2. **Параметры ядра (GRUB) и BIOS:**
   * В BIOS включен **PCIe PTM**, отключен **Spread Spectrum (SSC)**, карты установлены в прямые линии PCIe CPU.
   * В GRUB отключены глубокие C-states (`processor.max_cstate=1 idle=poll`) и выделены изолированные ядра (`isolcpus`, `nohz_full`, `rcu_nocbs`).
