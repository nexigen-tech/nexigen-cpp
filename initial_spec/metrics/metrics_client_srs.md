# Спецификация требований к клиентской библиотеке метрик (nexigen::metrics SDK)

## 1. Введение и область применения
Настоящий документ определяет требования к функциональности, политикам доступа, структуре разделяемой памяти и программному интерфейсу (API) встраиваемой клиентской библиотеки **`nexigen::metrics`**. Библиотека линкуется с дочерними процессами платформы и обеспечивает высокопроизводительную инструментацию кода. Архитектура базируется на шаблонном метапрограммировании (политиках компиляции) и размещении данных в разделяемой памяти **Eclipse iceoryx2**, обеспечивая экстремально низкие задержки вплоть до долей наносекунды.

---

## 2. Политики конфигурирования метрик (Compile-Time Policies)

Каждая метрика при объявлении в коде параметризуется тремя политиками (через шаблоны C++ или обобщенные типы Rust), определяющими её поведение и стоимость обновления:

*   **REQ_METC_001: Политика конкурентного доступа (`ConcurrencyPolicy`)**
    *   **Описание:** Разработчик должен иметь возможность явно указать, обновляется ли метрика из одного конкретного потока или из нескольких потоков одновременно, чтобы избежать лишних аппаратных блокировок шины памяти.
    *   **Критерий приемки:** 
        1. **`ConcurrencyPolicy::MultiThreaded` (по умолчанию):** Обновление выполняется через атомарные RMW-инструкции процессора (`fetch_add`, `compare_exchange_weak` с префиксом `LOCK`). Безопасно при вызове из любых потоков процесса.
        2. **`ConcurrencyPolicy::SingleThreaded`:** Предназначена для метрик, закрепленных за одним эксклюзивным рабочим потоком (например, RT-потоком на изолированном ядре). Обновление выполняется через чтение локальной переменной, сложение в регистре CPU и одиночную инструкцию `atomic::store(val, std::memory_order_relaxed)` без аппаратного сброса кэш-линий.

*   **REQ_METC_002: Политика доступа со стороны приложения (`AccessPolicy`)**
    *   **Описание:** Библиотека должна разграничивать метрики, предназначенные исключительно для внешней выгрузки, и метрики, значения которых могут считываться самим приложением для внутренней логики и самодиагностики.
    *   **Критерий приемки:** 
        1. **`AccessPolicy::WriteOnly` (по умолчанию):** Интерфейс класса метрики предоставляет только мутирующие методы (`Increment()`, `Set()`, `Observe()`). Методы чтения (`Get()`, `Load()`) отсутствуют на уровне компиляции, предотвращая случайное использование телеметрии в бизнес-логике.
        2. **`AccessPolicy::ReadWrite`:** Интерфейс дополнительно открывает неблокирующие методы чтения текущих значений (`Get()`, `GetMin()`, `GetMean()`) для самого дочернего процесса.

*   **REQ_METC_003: Политика сброса при чтении демоном (`ResetPolicy`)**
    *   **Описание:** Метрика должна поддерживать как непрерывное накопление за всё время жизни процесса, так и интервальный сбор (сброс значения в ноль при каждом считывании демоном `MetricsDaemon`).
    *   **Критерий приемки:** 
        1. **`ResetPolicy::Cumulative`:** Значение монотонно копится или хранит последнее состояние до завершения процесса.
        2. **`ResetPolicy::ResetOnRead`:** При каждом цикле опроса со стороны `MetricsDaemon` накопленное состояние атомарно сбрасывается в начальное значение (для фиксации чистых дельт и экстремумов за конкретное окно времени `scrape_interval_ms`). Для составных метрик реализуется через неблокирующее переключение двух теневых буферов (Ping-Pong Double Buffering) в разделяемой памяти.

## 3. Типы и примитивы метрик (Metric Types)

*   **REQ_METC_004: Базовые числовые примитивы (`Counter` и `NumericGauge`)**
    *   **Описание:** Поддержка классических скалярных показателей.
    *   **Критерий приемки:** 
        1. **`Counter<Concurrency, Access, Reset>`:** 64-битное беззнаковое целое (`uint64_t`). Методы: `Increment()`, `Add(uint64_t)`.
        2. **`Gauge<T, Concurrency, Access, Reset>`:** Шаблонный индикатор для типов `int64_t` и `double`. Методы: `Set(T)`, `Add(T)`, `Sub(T)`.

*   **REQ_METC_005: Строковый индикатор состояний (`StateGauge` / `StringGauge`)**
    *   **Описание:** Специализированный тип метрики `Gauge` с хранимым значением в виде строки фиксированного размера (массива символов) для отслеживания текстовых режимов работы, текущих профилей или диагностических статусов (например, `"RTK_FIXED"`, `"CALIBRATING"`).
    *   **Критерий приемки:** 
        1. Хранение строки в контейнере `FixedSizeByteString<32>` (до 32 символов ASCII/UTF-8 без динамических аллокаций в куче).
        2. Для предотвращения «порванного чтения» (torn read), когда `MetricsDaemon` читает строку в момент её перезаписи приложением, запись и чтение защищаются легковесным неблокирующим протоколом **`SeqLock` (Sequence Lock)** на базе атомарного счетчика версий.

*   **REQ_METC_006: Метрика описательной статистики (`DescriptiveStatistics`)**
    *   **Описание:** Агрегирующая метрика, которая в реальном времени отслеживает статистическое распределение записываемых в нее величин: количество (`count`), среднее арифметическое (`mean`), минимум (`min`), максимум (`max`) и среднеквадратичное отклонение (`std` / `stddev`).
    *   **Критерий приемки:** 
        1. При вызове `Observe(double val)` в рабочем потоке не сохраняется массив всех точек и не вычисляются тяжелые квадратные корни.
        2. В разделяемой памяти обновляются только 5 атомарных аккумуляторов: `count`, `sum` ($\sum x$), `sum_of_squares` ($\sum x^2$, либо потоковый алгоритм Уэлфорда для численной стабильности), `min` и `max`.
        3. Финальное извлечение квадратного корня для `std` ($\sigma = \sqrt{\frac{\sum x^2}{N} - \mu^2}$) и деление для `mean` перекладываются на `MetricsDaemon` при чтении (или вычисляются лениво при вызове `GetStdDev()` в режиме `AccessPolicy::ReadWrite`).

*   **REQ_METC_007: Классическая и Экспоненциальная гистограммы (`Histogram` & `ExponentialHistogram`)**
    *   **Описание:** Метрики для точного анализа профилей задержек (Latency Percentiles: p50, p90, p99) с фиксированным и логарифмическим масштабированием корзин.
    *   **Критерий приемки:** 
        1. **`LinearHistogram<N>`:** Пользователь задает до `N` (например, 16) произвольных границ корзин при инициализации.
        2. **`ExponentialHistogram<Scale>`:** Границы корзин не задаются вручную, а растут экспоненциально по формуле $base^i$, покрывая огромный динамический диапазон (от 1 наносекунды до 10 секунд) в компактном статическом массиве из 64 или 128 корзин.
        3. **Аппаратное вычисление индекса за O(1):** В `ExponentialHistogram` вычисление номера корзины в рабочем потоке не должно использовать математическую функцию `std::log()`. Индекс вычисляется за 1–2 такта CPU с помощью битовых операций над порядком числа IEEE-754 или аппаратной инструкции подсчета ведущих нулей (`__builtin_clzll` / `std::countl_zero`).

## 4. Архитектура памяти и гарантии реального времени (Memory Layout & RT Guarantees)

*   **REQ_METC_008: Выравнивание по кэш-линиям и защита от False Sharing**
    *   **Описание:** Размещение метрик в разделяемой памяти `iceoryx2` должно исключать взаимное замедление ядер процессора.
    *   **Критерий приемки:** Каждый экземпляр метрики в сегменте разделяемой памяти выравнивается по границе 64 байта (`alignas(64)`). Для метрик с политикой `ResetOnRead`, использующих двойную буферизацию (два банка данных `Bank A` и `Bank B` + атомарный индекс активного банка), каждый банк данных также выравнивается на 64 байта.

*   **REQ_METC_009: Бюджет времени выполнения в RT-потоках (WCET Limits)**
    *   **Описание:** Обновление любой метрики должно быть полностью детерминированным по времени (Wait-Free).
    *   **Критерий приемки:** Максимальное время выполнения (WCET) в рабочем потоке:
        *   `Counter` / `Gauge` (`SingleThreaded`): **<= 1 нс**.
        *   `Counter` / `Gauge` (`MultiThreaded`): **<= 5 нс**.
        *   `DescriptiveStatistics` / `ExponentialHistogram`: **<= 12 нс**.
        *   `StateGauge` (копирование 32 байт под `SeqLock`): **<= 15 нс**.

*   **REQ_METC_010: Автоматическая инструментация инфраструктурных слоев**
    *   **Описание:** Смежные библиотеки платформы (`nexigen::com`, `nexigen::log`, `nexigen::phm`) автоматически регистрируют в реестре процесса внутренние метрики здоровья (размеры очередей `iceoryx2`, счетчики потерь пакетов, задержки отправки).
