# Proposal

## Why

Платформа планирует перевести наблюдаемость (лог/метрики/трейс) на центральные демоны поверх iceoryx2, следуя `initial_spec/` (LOGC/LOGD/METC/METD/TRCC/TRCD). Перед выбором транспортной модели — прямой `loan_uninit → send` (вариант «a», строго по `REQ_LOGC_005` «без локальных буферов») против worker-publish (вариант «b», сохраняет текущий SPSC-ring) — нужны реальные числа горячего пути. Сейчас producer логгера измерен и гейтится на ≤20 нс (внутрипроцессный ring), а латентности iceoryx2-транспорта (`loan_uninit`/`send`/`notify`) в проекте нет ни одного замера.

## What Changes

- Добавляется микробенч горячего пути логгера поверх транспорта `nexigen::com` (iceoryx2): `loan_uninit() → fill(256Б) → send()` и полный путь `send + EventNotifier::notify()`.
- Для сравнения измеряется альтернатива worker-publish: продюсер остаётся на ring (как сейчас), а фоновый воркер выполняет `loan/send/notify`.
- Базой сравнения служит существующий замер pack+push (~20 нс) из `tests/logging/latency_test.cpp`.
- Изменения только в тестовой инфраструктуре; **никакого продакшн-кода, API или зависимостей не меняется** (чистый замер-спайк).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

> Этот change — измерительный спайк: он не меняет поведение системы и не вводит долгоживущих требований, поэтому спеки пропускаются (`skip_specs: true`). Решение о транспортной модели и соответствие числам `REQ_LOGC_006` (WCET ≤1.5 мкс) будет зафиксировано отдельным change'ем после получения цифр.

## Impact

- **Код**: новый `tests/com/latency_test.cpp` (по образцу `tests/{logging,tracing,metrics}/latency_test.cpp`) + регистрация теста в `tests/CMakeLists.txt`.
- **Производительность**: нулевое влияние на прод-код — бенч собирается только в тестовых конфигурациях и сам не аллоцирует в измеряемом окне (наследует rdtsc-харнес).
- **API/зависимости**: без изменений; использует уже существующие `nexigen::com::Publisher` и `nexigen::com::EventNotifier`.
- **Гейты**: замер добавляется под строгим гейтом `NEXIGEN_STRICT_LATENCY_TESTS`; в Debug/TSan/ASan конфигурациях только печатает медианы, не ассертит (как существующие latency-сьюты).
